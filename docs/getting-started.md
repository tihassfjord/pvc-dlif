# Getting started

From a clone to a first result. Budget about half an hour for the install and
the synthetic run; the real dataset takes considerably longer.

---

## 1. Install

PETPVC is a compiled toolbox distributed through conda-forge and is not on PyPI,
so conda builds the environment and pip installs this package into it.

```bash
git clone https://github.com/<your-username>/pvc-dlif.git
cd pvc-dlif

conda env create -f environment.yml
conda activate pvc-dlif
pip install -e ".[all]"
```

Check three things before going further:

```bash
petpvc --help                          # the toolbox is on PATH
python -c "import torch; print(torch.cuda.is_available())"
python -m pytest tests/                # ~100 tests, no dataset needed
```

`petpvc` missing is not fatal — the pipeline falls back to a NumPy
implementation of the same two algorithms and says so loudly — but anything you
report should come from the toolbox. `torch` missing disables stages 04 and 05
only; everything else still runs.

---

## 2. Prove the wiring on synthetic data

Before pointing anything at the real archive, generate a dataset in the same
format and run the whole pipeline over it:

```bash
python tests/make_synthetic_dataset.py --out /tmp/synthetic \
       --n-scans 8 --write-config configs/synthetic.yaml

python scripts/run_all.py --config configs/synthetic.yaml --from 00 --to 03
```

Expect stage 01 to report `agreement_with_distributed_median_r` at 0.9999 or
better — the synthetic data is generated by the same pure-crop transformation
the real preprocessing turned out to be, so recovering the window should be
exact. Anything lower means the crop fitting is broken.

Stage 02 stops if PETPVC is not installed rather than quietly substituting the
fallback. Add `--backend numpy` to that stage to get past it during a wiring
check; do not report numbers produced that way.

Stages 04 and 05 need the DLIF repository and its weights. If you have them,
point `paths.dlif_repo` in `configs/synthetic.yaml` at the clone, set
`dlif_grid.shapes` to `[[64, 48, 48]]` and `retrain_model.input_shape` to
`[64, 48, 48]` (the synthetic reference is 64 slices, so there is no 96-slice
window to cut), and the chain runs through to 08:

```bash
python scripts/04_infer_baseline.py --config configs/synthetic.yaml --device cpu
python scripts/05_retrain.py --config configs/synthetic.yaml --folds 1 --runs 2 --epochs 3 --device cpu
python scripts/06_evaluate.py  --config configs/synthetic.yaml --skip-kinetics
python scripts/08_report.py    --config configs/synthetic.yaml
```

Folds are numbered from 1. What all of this proves is that the data layer,
the model adapter, the training loop and the evaluation read and write the
same files; the numbers mean nothing. If this fails, fix it here rather than
on a run that takes days.

## 3. Point it at the real data

```bash
cp configs/example.yaml configs/thesis.yaml
```

Set four paths, and nothing else:

```yaml
paths:
  dicom_root:     "E:/.../aif-mice-dicom-pet"   # dPET_dcm_<ID> exports
  dlif_data_root: "E:/.../data"                 # AIF_SUV/ IMG_SUV_*/ VOI_SUV/
  dlif_repo:      "E:/.../DLIF-main"            # the model and its weights
  work:           "E:/.../thesis_work"          # generated output
```

Windows paths with forward slashes are fine. See [`data.md`](data.md) for what
each of those folders has to contain.

Then take a small pass first:

```bash
python scripts/run_all.py --pilot
```

Pilot mode uses eight scans, one fold, one repeat and five epochs. It finishes
in minutes and tells you whether the real data flows through. Its numbers are
not results, and the config records that they were produced in pilot mode.

---

## 4. The real run

```bash
python scripts/run_all.py
```

Every stage is resumable: work whose output already exists is skipped, so a run
interrupted at stage 05 picks up where it stopped rather than starting over.

Rough costs on one machine, 70 scans:

| Stage | What dominates | Order of magnitude |
|---|---|---|
| 00 | reading DICOM headers | seconds |
| 01 | DICOM decode + crop fitting | ~1 h |
| 02 | 70 scans × 42 frames × 2 methods × 3 iteration counts | several hours |
| 03 | array slicing | minutes |
| 04 | forward passes | minutes |
| 05 | 3 conditions × 10 folds × 10 repeats | days on one GPU |
| 06 | statistics and bootstrap | minutes |
| 07 | motion subset | minutes |
| 08 | figures and tables | seconds |

Stage 05 is the one to plan around. `--folds`, `--runs` and `--epochs` cut it
down when you need an answer sooner, at the cost of the variance estimate.

## 5. Or use the GUI

```bash
python gui/run_gui.py        # from a clone      (run_gui.bat on Windows)
pvc-dlif-gui                 # once installed
```

Four tabs. Nothing in them contains science — every button calls the same
library function or stage script the command line does.

**Setup** — the four paths and the handful of parameters worth changing
without opening the YAML (primary iteration count, methods, folds, runs,
device, motion-affected IDs). Saving keeps every comment in the file and
refuses an edit that would not load. *Run preflight check* tells you, item by
item, what is installed and what is not, with the exact fix for each — on a
fresh machine this is where you find out PETPVC is missing.

**PVC** — correct one image, a folder, or a set of thesis scans ticked from
the manifest. Method, iterations (or a sweep), alpha, PSF, backend and workers
are on screen. Runs through the same `run_batch` stage 02 uses, so outputs are
resumable and land in the same layout, with a diagnostics JSON beside each.
Stop halts at the next scan boundary. The Results tab shows per-scan recovery
and noise amplification; Per frame shows every frame.

**Pipeline** — the nine stages with a status light and a count read from the
work folder every time, so it survives a crash or a stage run from a terminal.
Two banners you cannot miss: *n usable* after stage 00, and the crop agreement
*r* after stage 01. Stages run *detached*: closing the window does not stop
them, and reopening the GUI re-attaches to the log and continues the queue.

**Analysis** — load `<work>/results`: the headline summary, every table
(sortable, exportable), the thesis figures drawn by the same functions stage
08 uses, and a per-scan browser (sort worst-first to find the cases worth
writing about). *Export for thesis* copies the figures and LaTeX fragments to
a folder ready for Overleaf.

## 6. Where the output lives

```
<work>/
  manifest.json               what exists and what is usable
  preprocessing_plan.json     the per-scan crop window — see docs/findings.md §4
  native/                     4D NIfTI at reconstructed resolution
  pvc/                        corrected series + per-frame diagnostics
  dlif_inputs/<condition>/    one input tree per condition
  models/<condition>/         checkpoints
  predictions/                pretrained.parquet, retrained.parquet
  results/                    curve_metrics, comparisons, bias_variance, summary.json
  report/                     thesis figures and \input-ready LaTeX tables
  logs/                       one log per stage run
```

Everything under `<work>` is generated and can be deleted and rebuilt. Every
output carries a `.provenance.json` naming the stage, the config hash and the
time it was written.

## Common problems

**`petpvc: command not found`** — the conda environment is not active, or
conda-forge did not provide a build for your platform. The pipeline continues
on the NumPy backend and warns; do not report those numbers.

**Stage 01 reports a low correlation for some scan.** It is telling you the
recovered crop does not reproduce that scan's distributed input. One scan at
0.97 is a known case (see [`findings.md`](findings.md) §3); several would mean
the archive does not match the distributed data and should be investigated
before going on.

**Stage 05 raises a shape error from inside torch.** The input shape and the
model do not match. The pretrained model takes 64 × 48 × 48 with two channels;
the retrained one takes 96 × 48 × 48 with one. `findings.md` §2 explains why.

**A stage says it is skipping everything.** That is resume working as intended.
Delete the relevant folder under `<work>` to force a rebuild.
